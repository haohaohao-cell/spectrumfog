这个模型证明了什么

一份部分可观测的电磁对抗仿真，参数全部虚构。它不预测任何真实系统， 但它能把几件在纸面上容易想当然的事，变成可以复算的数字。

下面每一条都附了命令——你可以自己跑出同样的结果，而不是信这份文档。

一、烧穿 ≠ 能检测

教科书常说"J/S = 1 是烧穿点"。01_duel 里（150 kW / 35 dBi 雷达，90 W 干扰机在 30 km， 1 m² 目标）：

量 值
J/S = 1 的烧穿半径 3.24 km
干扰下 Pd = 0.5 的距离 0.75 km
30 km 处的 J/S 85.6（19.3 dB）
30 km 处的 Pd 1.2 × 10⁻⁶

差 4 倍多。原因不复杂：J/S = 1 只把信噪比砍掉 3 dB，而这个 Swerling I 闭式要 Pd = 0.5 大约需要 20 dB。"目标在烧穿圈内"和"雷达看得见它"是两件事， 中间隔着一个检测概率。

spectrumfog run scenarios/01_duel.yaml     # 三张图里能直接看到这个差距

二、1 W 干扰机压住 150 kW 雷达——但那是因为模型里没有处理增益

02_standoff 里只有 1 W，干扰机从 60 km 压到 4 km，雷达的跟踪边界从 20.5 km 缩到 5.3 km，12 km 处的目标在 t = 170 s 丢失。

看着不合理，其实合理：100 MHz 上摊开的 1 W 落进 2 MHz 接收机只剩 20 mW， 而 12 km 处的回波本身只有 −67 dBm。这是"没有处理增益"这个前提的产物，不是战果。

所以 0.3.0 加了 processing_gain_db，默认 0（既有数字一个不动），用 07_gain 做对照：

处理增益 J/S @ 30 km Pd 601 帧命中
0（01_duel） 85.6 1.2e-6 0
20 dB 0.856 1.7e-3 2
40 dB（07_gain） 0.0086 0.849 505

中间那行是这条的价值所在：20 dB（功率 ×100、烧穿距离 ×10）几乎什么都没改变。 "加个 20 dB 就翻盘"是错觉，真实门槛在 40 dB 附近。

spectrumfog sim scenarios/07_gain.yaml --replay out/gain.jsonl

三、"被发现一次"和"被跟踪"不是一回事

单帧定位点只是量测。加一层航迹（卡尔曼 + 门限 + 关联 + 起批/确认/滑行）之后， "漏一帧"和"跟丢了"才成为两个概念。

08_duel_2p 把蓝方雷达也变成决策者（关机 / 半功率 / 满功率），只在蓝方开机时结算， 两边都在挑时间。暴露的判定方式决定了这个博弈有没有意义：

暴露定义 蓝方最好成绩 结果
被定位一次 约 −4 150 kW 雷达永远被看见 → 博弈退化成"谁都不开灯"
被确认跟踪（3 次命中） +58.8 脉冲式开机成为甜点：看得见目标，凑不够 3 次命中

同一个环境，只换暴露的定义，最优策略从"别开机"变成"每 5 帧开 1 帧"。 指标定义不是中立的——它决定了好策略长什么样。

红方 蓝方 红方得分 蓝方得分
一直满功率压制 一直开机 −4.0 −304.0
一直满功率压制 每 5 帧开 1 帧 −244.0 −1.2
关机 每 5 帧开 1 帧 0.0 +58.8

四、"雷达看到的"可以是假的

转发式诱饵被照到后延迟 τ 再放大转发，雷达量到的距离是 R + c·τ/2。 06_decoy 里诱饵本体在 22 km，range_offset_m = 3000：
诱饵本体 22.0 km
蓝方雷达航迹起批位置 25.0 km
诱饵回波 / 真目标回波 325×
蓝方雷达航迹中假航迹占比 100%

蓝方雷达全程锁着一条不在那里的航迹。而它的代价在观测侧：诱饵转发时也在辐射， 所以它自己会被 ESM 解出来——只是精度差到（最好 13 km）连航迹都起不来。

诱饵骗得了雷达，骗不了 ESM 的航迹。欺骗是对某一部传感器成立，不是对"对方"成立。

五、一个负结果：自训练学不出"脉冲"

线性 softmax + CEM，红蓝交替，纯 numpy（bench/selfplay.py）。5 代之后：

代        红方        蓝方     蓝方开机
  0    -122.9    -218.2      75%
  5      46.9     -81.1     100%

两边都在变强，但蓝方学会的是"把功率降到半档"，不是"脉冲式开机"。 加 sin/cos 时间基函数（让它能表达周期性）也没用。三个原因写在 评测文档里：无记忆策略、每代样本太少、逐帧奖励没有价值函数—— 脉冲的收益是"省下未来的暴露"，单步贪心看不见。

这条和前面四条一样重要：它说明了这个环境能训，但"学出策略"不是加个优化器就行的。

六、为什么这些数字可信

不是"看起来合理"，是三条机制：

  1. 确定性 replay：t = index·dt（不累加）、单一 seeded RNG、一行一事件。 同一想定 + 同一 seed 逐字节一致，有测试守着。没有这条，任何复盘都是编故事。
  2. 一份物理：CLI、网页、Gym 环境调的是同一批函数。网页是 Python 预编译的查表 + 插值， 所以网页和命令行的数不可能对不上。
  3. 可校验的提交物：排行榜的提交带每份想定的内容指纹（解析后的规范化 JSON，不是文件字节）， 改一个参数就会被 --verify 挡下来，改注释不会。

七、这些结论不适用什么

  • 参数全是虚构的，不代表任何真实装备；
  • 没有实测校验，只有"公式自洽 + 单元测试"；
  • 单站、矩形谱、无多径、无极化；诱饵只到"假回波"，不是"假航迹"；
  • 自训练不是强化学习的最优实践（无记忆、无价值函数）；
  • 所有"最优策略"都是在极小的基线集合上说的，不是博弈论意义上的均衡。

八、自己复现

git clone https://github.com/haohaohao-cell/spectrumfog && cd spectrumfog
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev,bench]"

pytest -q                                          # 230 项，CI 里含覆盖率 91.7%
spectrumfog run scenarios/01_duel.yaml             # 第一、二条
spectrumfog sim scenarios/07_gain.yaml --gif       # 处理增益对照
spectrumfog bench --suite scenarios/suite_v1.yaml  # 排行榜基准
